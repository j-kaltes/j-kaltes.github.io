Does Juggluco need the Internet or a Juggluco account to receive sensor readings?
FAQ-002Direct link

No Internet connection or Juggluco account is needed for local sensor reception. The sensor communicates over Bluetooth. Glucose broadcasts to another app on the same phone also work without Internet access.

Cloud uploads and remote following are separate functions. A LibreView account identity can still be needed when taking over a running Libre 3 sensor; see FAQ-019.

005

How do I move Juggluco and its history to a new phone?
FAQ-005Direct link

Transfer your data before stopping the old phone’s sensor connection. Use left middle menu → Mirror → AutoQR, or the ADB transfer procedure in the phone-migration instructions.

  1. Transfer the archive and sensor information from the old phone.
  2. Check LibreView settings on the new phone. The described ADB transfer includes credentials; mirroring does not. For Libre 3, retain the sensor’s activation account ID.
  3. Stop sensor reception on the old phone, then enable left menu → Sensor → Use Bluetooth on the new phone.
  4. When no longer needed, remove the migration connection through Mirror → select connection → Modify → Delete.

A new NFC scan is not automatically necessary after a successful transfer of sensor information. Forget is not the handover command; see FAQ-082.

Scope & version noteThe takeover procedure depends on the sensor. CareSens Air was explicitly excluded from the general takeover advice; do not assume every sensor can be transferred this way.

What information should I send when a sensor will not connect?

Send the Sensor screen from the device that should receive directly, together with the information needed to reproduce the problem:

  4. Logs from a compatible logging build when the screenshot is not enough; see FAQ-014.

An isolated error number, an old crossed-out status, or a log ending before the failure is not enough to identify the cause.

009

What are the usual first steps when Bluetooth readings stop?
FAQ-009Direct link

First open left menu → Sensor and check whether this is a connection failure or a sensor that is connected but not supplying glucose; see FAQ-011.

For a connection failure, the usual checks are to switch Android Bluetooth off and on, force-stop another app that could be connecting to the same sensor, and reboot the phone. After rebooting, the other app may need to be force-stopped again.

When switching a Libre 3 sensor between apps, rescan it in Juggluco after the other app has scanned it.

Scope & version noteThese steps are not a cure for invalid sensor measurements. Do not apply them to interrupting an insulin-pump or treatment-controller connection; that setup needs separate assessment.

Which background settings should I check?
FAQ-010Direct link

Do not silence the Juggluco notification as a troubleshooting shortcut. Bring the app to the foreground temporarily to see whether reception changes.

011

Does “no glucose” always mean a Bluetooth connection error?
FAQ-011Direct link

No. A sensor-output problem and a Bluetooth connection problem are different. A sensor can remain connected and exchange Bluetooth traffic without supplying new glucose measurements.

For the Libre 3 invalid-measurement condition described in support, interpretation happens inside the sensor: Juggluco does not receive an ordinary glucose value with a reliability flag that it can simply ignore.

Check the Sensor screen and the sequence of events. A gap, “sensor not ready,” or a protocol-state number alone does not establish that every case has the same cause. A confirmed failed-sensor case may need to be referred to Abbott.

014

How do I collect Juggluco logs for a bug report?
FAQ-014Direct link

Install a compatible logging build as an update, without uninstalling. Logging builds are listed in the download page’s bugreport section.

  1. Reproduce the problem and allow enough time to capture the failure.
  2. Open left menu → Settings → Logging.
  3. Save trace.log and logcat.txt.

For a native crash, a log filtered only to Juggluco’s process ID can omit the crash report. Collect full logcat or the crash buffer:

adb logcat -b crash

You can clear or disable logging from the Logging screen without reinstalling. See FAQ-015 for official-app Bluetooth logs and FAQ-127 for crash reports.

015

How do I capture the official app’s Bluetooth traffic?
FAQ-015Direct link

To compare a sensor that works in its official app but not in Juggluco:

  1. Enable Android developer options and Bluetooth HCI snoop logging.
  2. Switch Bluetooth off and on so the logging setting takes effect.
  3. Run the official app and reproduce the communication. Do not run Juggluco at the same time: it can interfere and make the traffic difficult to attribute.
  4. With ADB installed, USB debugging enabled and the phone connected, run:
adb bugreport

Look in the resulting ZIP for btsnoop_hci.log and btsnoop_hci.log.last. One possible location is FS/data/misc/bluetooth/logs; it can vary.

Scope & version noteA complete Android bug report can contain unrelated private information. Review what you share; the Bluetooth log files are the evidence needed for this comparison. Do not interrupt a treatment-controller setup to collect these logs.

019

Why must the Libre 3 account ID stay the same?
FAQ-019Direct link

The account-related number used when scanning must match the one used to activate that Libre 3 sensor. For a sensor started in the standalone Libre 3 app while logged in, enter that LibreView account in left menu → Settings → Exchange data → LibreView and retrieve its account ID.

Changing credentials later does not itself change the sensor’s activation identity. Zero or an arbitrary new ID is not a replacement for the ID of an already-running sensor.

The upload account is a different matter. You can upload to a LibreView account that is not associated with the sensor’s activation account ID. Do not change the activation ID merely to change the upload destination.

Why are some old feature requests closed even though the requested feature is absent?
FAQ-133Direct link

Closed does not necessarily mean implemented or fixed. A thread may close after an explanation, a negative answer, a redirect, or a proposed workaround.

For example, a closed request for custom rapid-rise alerts pointed to writing an app that receives broadcasts, rather than announcing a new built-in alarm.

Read the final answer and any named release outcome. An accepted answer or a posted patch is not by itself evidence that a feature was released.

About this FAQ

These answers summarize Juggluco maintainer support correspondence and public GitHub replies available through 28 September 2026. Dates identify the source information, not the last time software was tested. Historical cases and unresolved compatibility questions are kept qualified rather than presented as universal fixes.

Menu names use the English interface. Check the sensor, region, app and version relevant to your setup. This FAQ covers software operation, not insulin dosing or treatment-controller configuration.

Use the question’s Direct link or Copy link when referring someone to an answer. GitHub background links are provided where available; private correspondence is not published.
