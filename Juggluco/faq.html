Does Juggluco need the Internet or a Juggluco account to receive sensor readings?
FAQ-002Direct link

Cloud uploads and remote following are separate functions. A LibreView account identity can still be needed when taking over a running Libre 3 sensor; see FAQ-019.

005

How do I move Juggluco and my data to a new phone?
FAQ-005Direct link

Transfer your Juggluco data before stopping the old phone’s sensor connection. Use left middle menu → Mirror → AutoQR, or the ADB transfer procedure in the phone-migration instructions.

  1. Transfer the Juggluco data and sensor information from the old phone.
  2. Check LibreView settings on the new phone. The ADB transfer includes the credentials; AutoQR/mirroring does not. For Libre 3, keep the activation account ID used for the running sensor.
  3. Stop sensor reception on the old phone, then enable left menu → Sensor → Use Bluetooth on the new phone.
  4. When the migration connection is no longer needed, remove it through Mirror → select connection → Modify → Delete.

If the sensor information was transferred successfully, a new NFC scan is not normally needed. Forget is not the handover command; see FAQ-082.

CareSens Air uses a different transfer procedure.

What information should I send when a sensor will not connect?
FAQ-008Direct link

Send the Sensor screen from the device that should receive directly, together with the information needed to reproduce the problem:

  1. Sensor type, phone/watch model, Android or Wear OS version, and Juggluco version from Settings → About.
  2. How long readings have been missing, whether the phone or watch should receive directly, and which other app/device has used the sensor.
  3. The exact message and the steps already tried. Capture left menu → Sensor before rescanning or changing settings.
  4. Logs from a compatible logging build when the screenshot is not enough; see FAQ-014.

An isolated error number, an old crossed-out status, or a log ending before the failure is not enough to identify the cause.

009

What are the usual first steps when Bluetooth readings stop?
FAQ-009Direct link

First open left menu → Sensor and check whether this is a Bluetooth connection failure or a sensor that is connected but not supplying glucose; see FAQ-011.

For a connection failure, try switching Android Bluetooth off and on, force-stop another app that could be connecting to the same sensor, and reboot the phone. After rebooting, the other app may need to be force-stopped again.

When switching a Libre 3 sensor between apps, rescan it in Juggluco after the other app has scanned it.

If the sensor is connected to an insulin pump or other treatment controller, do not disconnect that controller merely as a Juggluco troubleshooting step.

011

Does “no glucose” always mean a Bluetooth connection error?
FAQ-011Direct link

No. A sensor-output problem and a Bluetooth connection problem are different. A sensor can remain connected and exchange Bluetooth traffic without supplying new glucose measurements.

With Libre 3, some invalid measurements are rejected inside the sensor. Juggluco does not receive an ordinary glucose value plus a reliability flag that it could simply ignore.

Check left menu → Sensor to see whether the connection itself is failing or whether the sensor is connected but not producing values. If the sensor itself has failed, Abbott support may be needed.

What should I do about NFC scan errors?
FAQ-012Direct link

Hold the sensor against the phone’s NFC element. Try toggling NFC or rebooting the phone. For the Libre 3 scan messages ending in “Try again,” scan again; report any different persistent message exactly.

For Libre 3, check the activation account ID separately; see FAQ-019. Forget concerns Bluetooth addressing and is not a general fix for NFC errors.

013

Does status 19 identify one particular fault?
FAQ-013Direct link

No. Bluetooth status 19 and NFC “ScanError 19” are different errors.

For Bluetooth, status 19 is a disconnect indication; the cause still has to be found. One useful check is whether another app or device is also trying to connect to the sensor. A crossed-out status may refer to an earlier disconnect rather than the current state.

For Libre 1 NFC, ScanError 19 was an exception that required logcat for diagnosis.

When reporting either error, include the exact message, sensor, device and what happened immediately before it.

014

How do I collect Juggluco logs for a bug report?
FAQ-014Direct link

Install a compatible logging build as an update, without uninstalling. Logging builds are listed in the download page’s bugreport section.

  1. Reproduce the problem and allow enough time to capture the failure.
  2. Open left menu → Settings → Logging.
  3. Save trace.log and logcat.txt.

For a native crash, a log filtered only to Juggluco’s process ID can omit the crash report. Collect full logcat or the crash buffer:

adb logcat -b crash

You can clear or disable logging from the Logging screen without reinstalling. See FAQ-015 for official-app Bluetooth logs and FAQ-127 for crash reports.

015

How do I capture the official app’s Bluetooth traffic?
FAQ-015Direct link

To compare a sensor that works in its official app but not in Juggluco:

  1. Enable Android developer options and Bluetooth HCI snoop logging.
  2. Switch Bluetooth off and on so the logging setting takes effect.
  3. Run the official app and reproduce the communication. Do not run Juggluco at the same time, because both apps can interfere with each other.
  4. With ADB installed, USB debugging enabled and the phone connected, run:
adb bugreport

Look in the resulting ZIP for btsnoop_hci.log and btsnoop_hci.log.last. One possible location is FS/data/misc/bluetooth/logs; the location can vary.

An Android bug report can contain unrelated private information. Review the files before sharing them. Do not disconnect an insulin pump or other treatment controller just to make this recording.

019

Why must the Libre 3 account ID stay the same?
FAQ-019Direct link

The account-related number used when scanning must match the one used to activate that Libre 3 sensor. For a sensor started in the standalone Libre 3 app while logged in, enter that LibreView account in left menu → Settings → Exchange data → LibreView and retrieve its account ID.

Changing credentials later does not itself change the sensor’s activation identity. Zero or an arbitrary new ID is not a replacement for the ID of an already-running sensor.

The upload account is a different matter. You can upload to a LibreView account that is not associated with the sensor’s activation account ID. Do not change the activation ID merely to change the upload destination.

020

How do I switch between Juggluco and the standalone Abbott Libre 3 app?
FAQ-020Direct link

For a compatible sensor with the correct Libre 3 activation account ID already configured:

  1. To move to Abbott’s standalone Libre 3 app, terminate that sensor in Juggluco, then scan it in Abbott’s app as a new sensor.
  2. To return to Juggluco, force-stop Abbott’s app and scan the sensor again in Juggluco.

Scanning supplies the information needed by the app that takes over the sensor; the two apps do not share one permanent connection.

This procedure is for the standalone Libre 3 app, not the combined Libre by Abbott app. See FAQ-021. If the activation account ID is unknown or wrong, see FAQ-022.
